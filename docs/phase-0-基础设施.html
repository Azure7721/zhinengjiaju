Phase 0 · Foundation

P0 · 基础设施与工程化

目标：从“只有设计稿和文档”到“一条命令能启动、能测试、能连数据库、能连 MQTT”的可复现工程。 本阶段不写业务页面，只把地基打牢。

2–3 天 monorepo CI DB / MQTT 环境预检

1. 阶段目标

  • pnpm workspaces + TypeScript + ESLint/Prettier 可运行
  • PostgreSQL（或兜底 SQLite）+ Prisma 迁移/seed 可重复
  • MQTT（Aedes 或 Mosquitto）可启动、可收发
  • server/admin/miniapp/device-engine 空壳可启动
  • CI 能跑 lint/typecheck/test/build
  • 环境记录与降级方案文档化

2. 前置条件

无。需要本机 Node 20+、pnpm、Git；微信开发者工具可后装。

环境探测（当前）： Node 24.14、pnpm 10.31、npm 11.9、Python 3.13、Git 2.33；Docker 未安装、WSL 未安装，虚拟化已启用。 本阶段先解决环境，所有安装/端口/账号记录到 docs/phase-0-环境记录.md。

3. WBS

时间任务产出
D1 上午安装/检查 Node、pnpm、Git、VS Code、微信开发者工具；Docker Desktop/WSL2 或降级环境预检脚本通过
D1 下午初始化 pnpm workspaces、tsconfig、eslint、prettier、vitest空包可 build
D1 晚创建 apps/server、admin、miniapp、device-engine 空壳；shared/contracts四个进程可启动
D2 上午PostgreSQL/Redis/MQTT；docker-compose 或本机；Aedes 双协议健康检查通过

D2 晚CI：install/lint/typecheck/test/build；脚本 check-envCI 绿
D3README、环境记录、端口表、启动说明；docs 导航新人可复现

6. 验收标准

  • 全新机器按 README 可安装并启动
  • 一条命令起 DB/MQTT/server；健康检查全绿
  • 迁移与 seed 可重复执行
  • CI 全绿
  • 端口表、环境记录、降级说明完整
  • 没有明文密钥入库/入仓

7. 风险

  • Docker/WSL 安装失败 → 立即切本机；本机也失败 → SQLite/Aedes 兜底，记录限制。
  • 端口冲突 → check-env 检测并给出占用进程。
  • Node/依赖版本冲突 → 固定 engines + lockfile。
  • Windows 路径/编码问题 → 统一 UTF-8、forward slash 脚本。
