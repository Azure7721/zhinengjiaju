08 · Device Test & BLE

设备测试与蓝牙联调

两条路径：T0 单机全虚拟，一台电脑跑通完整信号链路；T1 ESP32 BLE， 开发板发真实蓝牙广播，手机小程序扫描/连接/配网。T0 是演示基线，T1 是硬件验证。

T0 必做 T1 建议 虚拟 BLE WebSocket ESP32 + NimBLE Python bleak

1. 测试策略

路径用途依赖优先级
T0 单机全虚拟同一台 PC 跑 server、admin、MQTT、设备引擎、小程序开发者工具；虚拟 BLE 走 WebSocket无硬件必做
T1 开发板 BLEESP32 作为 BLE 外设；手机小程序扫描/连接；配网后 WiFi + MQTTESP32 + 手机 + 蓝牙建议
T2 混合PC 服务端 + ESP32 + 手机 + 管理后台T0 + T1可选
T3 异常/稳定性断连、超时、错误 token、重复广播、MQTT 断线、重启T0/T1必做

2. T0 单机全虚拟

2.1 服务与端口

服务端口说明
NestJS API / WebSocket3000http://127.0.0.1:3000，WS /ws
管理后台 Vite5173http://127.0.0.1:5173
MQTT Broker（Aedes）1883 / 8888TCP / WebSocket
虚拟 BLE WebSocket7001ws://127.0.0.1:7001/virtual-ble
PostgreSQL5432或 SQLite 兜底
Redis6379可先内存替代
小程序开发者工具—API 基址 http://127.0.0.1:3000

2.2 启动顺序

  1. 数据库/Redis：Docker Compose 或本机服务；跑迁移与 seed。
  2. MQTT：Aedes 以 ws/tcp 双协议启动。
  3. server：订阅 MQTT，启动 REST/WS，健康检查 /health。
  4. device-engine：注册 4+1 个虚拟设备，开始 telemetry。
  5. admin：Vite 启动。
  6. miniapp：pnpm dev:mp-weixin，微信开发者工具打开 dist/dev/mp-weixin。
  7. 开发者工具设置：勾选“不校验合法域名、web-view、TLS 版本以及 HTTPS 证书”。

所有服务可用 pnpm dev（concurrently）+ scripts/check-env.ts 做端口/健康检查。

2.3 虚拟 BLE 协议

用 WebSocket 模拟 GATT 语义；小程序端 platform/ble 通过环境变量切换真实/虚拟实现，业务代码不变。

消息方向载荷
scan.startclient → server{ type, serviceUUID }
scan.resultserver → client{ devices:[{ deviceId, name, rssi, serviceUUID }] }
connectclient → server{ deviceId }
connectedserver → client{ deviceId }
discoverclient → server{}
servicesserver → client{ services:[{ uuid, characteristics }] }
read / value双向{ serviceId, characteristicId, value? }
writeclient → server{ serviceId, characteristicId, value }
notifyserver → client{ characteristicId, value }
disconnect双向{ deviceId, reason }

2.4 虚拟设备

  • 4 个标准设备：空调、窗帘、电视、净化器。
  • 1 个“未知能力”设备：capability 不在注册表，验证通用降级控件。
  • 设备引擎每 2–5 秒发 telemetry；支持手动注入峰值/断连。
  • 管理后台“设备模拟器”页可新增/删除虚拟设备、发信号、断连。
同一台电脑的通信： 小程序开发者工具访问 127.0.0.1，server 与 MQTT 也监听本机； 虚拟 BLE 走 WebSocket，不经过真实蓝牙栈。这样不需要手机/开发板也能完整演示。

3. T1 ESP32 BLE

3.1 硬件

物料建议用途
开发板ESP32-C3 / ESP32-S3BLE 5.0 外设
USB 线数据线烧录/供电
传感器（可选）DHT22、PM2.5真实温湿度/空气质量
OLED（可选）0.96" I2C显示配网状态
手机iOS / Android微信真机调试

没有传感器时，固件内置正弦/随机信号，保证演示可用。

3.2 固件与 GATT

PlatformIO + Arduino/NimBLE（或 ESP-IDF）。上电广播自定义 Service UUID 与设备名。

UUID属性内容
FFF0Service主服务
FFF1ReadDeviceInfo：{ deviceId, model, firmware, capabilities }
FFF2WriteProvision：{ ssid, password, token, serverUrl }
FFF3WriteCommand：{ cmdId, capability, command, params }
FFF4NotifyTelemetry：{ deviceId, ts, state }
FFF5NotifyAck：{ cmdId, status, error? }

3.3 配网流程

广播→ 手机扫描→ 连接→ 读设备信息→ 写 WiFi/token→ 板子入网→ MQTT 上线→ 遥测/命令

板子加入同一局域网后连接 PC 的 mqtt://<PC-IP>:1883；服务端地址不能用 127.0.0.1。

3.4 小程序 BLE 调用序列

uni.openBluetoothAdapter({ success: startScan });

uni.startBluetoothDevicesDiscovery({
  services: [SERVICE_UUID],
  allowDuplicatesKey: false,
});

uni.onBluetoothDeviceFound((res) => {
  res.devices.forEach((d) => {
    if (d.advertisServiceUUIDs?.includes(SERVICE_UUID)) addCandidate(d);
  });
});

uni.createBLEConnection({ deviceId, timeout: 10000 });
uni.getBLEDeviceServices({ deviceId });
uni.getBLEDeviceCharacteristics({ deviceId, serviceId });

uni.notifyBLECharacteristicValueChange({
  state: true, deviceId, serviceId,
  characteristicId: TELEMETRY_UUID,
});
uni.onBLECharacteristicValueChange((res) => decode(res.value));

uni.writeBLECharacteristicValue({
  deviceId, serviceId,
  characteristicId: PROVISION_UUID,
  value: encode(payload),
});
  • 小程序只支持 BLE，不支持经典蓝牙。
  • Android 6+ 扫描需定位权限且定位开启；Android 12+ 需 BLUETOOTH_SCAN/CONNECT；iOS 需蓝牙权限。
  • deviceId 在 iOS/Android 不稳定，不能作为业务主键；业务主键用设备上报的 serial。
  • 默认 MTU 23（有效载荷 20 字节），JSON 需分片；Android 可 uni.setBLEMTU 协商。
  • 开发者工具对 BLE 支持有限，T1 必须真机。

6. 验收门槛

  • T0 全部通过后才进入 T1；T0 是演示必须项
  • T1 至少通过 1.1–1.4
  • 设备添加后数据库可查，user/family/home 正确
  • 命令幂等，重复 cmdId 不重复执行
  • 断连/超时/错误 token 有可见反馈
  • 扫描 <5s、连接 <10s、遥测 <2s、ack <1s（本地）
  • 解绑后停止推送，后台可审计

7. 故障注入

虚拟设备

  • 断连、延迟、丢包
  • 错误 JSON、超大 payload
  • 重复 cmdId、错误 token
  • 设备离线/重启

基础设施

  • MQTT broker 停止、QoS 0/1 对比
  • server 重启、DB/Redis 不可用
  • 端口冲突、防火墙拦截
  • 手机权限拒绝/蓝牙关闭

UI 必须覆盖：扫描中、连接中、配网中、成功、失败、重试、离线、无权限。

8. 限制与风险

  • 微信开发者工具不能完整模拟 BLE，T1 必须真机。
  • 手机不能访问 PC 的 127.0.0.1，T1 用同一局域网 IP 或内网穿透。
  • Windows BLE 依赖蓝牙适配器/驱动；bleak 也可能受系统限制。
  • 没有 ESP32 时，T0 仍可完成全部演示，T1 作为加分项。
  • 设备绑定与信号链路必须以后端/数据库为准，不能只在前端“假装”。
  • 真实环境需 HTTPS/域名白名单；本地开发用开发者工具免校验。

10. 测试数据与重置

  • 种子：2 个用户、2 个家庭、4 类设备 + 1 未知能力设备。
  • 账号：userA/userB、admin 四角色；密码只用于本地。
  • 重置脚本：清空遥测/命令/场景执行，保留型号与设备。
  • 测试后清理虚拟设备、解绑测试设备，避免污染演示数据。
