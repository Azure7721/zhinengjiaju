Phase 5 · Integration & Delivery

P5 · 联调、测试与交付

目标：从“各模块能跑”到“端到端可演示、可部署、可复现”。T0 全链路必须通过， T1 至少证明开发板 → 手机小程序 → 服务端；最后交付体验版与演示脚本。

5–6 天 T0 / T1 E2E 安全 / 性能 体验版

1. 阶段目标

  • T0 单机全链路全部通过
  • T1 ESP32 至少扫描/连接/读取/配网/遥测/命令
  • 登录 → 添加 → 控制 → 场景 → 后台可见 端到端通过
  • 权限/安全/性能检查通过
  • Docker/本机部署可复现
  • 微信体验版二维码可用
  • 演示脚本一次走通，文档齐全

2. 前置条件

P3 与 P4 核心功能完成；P2 信号链路可用。

3. WBS

时间任务产出
D1T0 全链路：启动、扫描、配网、绑定、遥测、命令、场景、重启T0 报告
D2T1 ESP32：广播、连接、FFF1/FFF2、MQTT、FFF4/FFF5T1 报告
D3E2E：Playwright 后台 + 小程序核心流程；边界/异常E2E 通过
D4安全（JWT/RBAC/限流/输入）、性能（列表/WS）检查报告
D5Docker/本机部署；HTTPS/域名/体验版可扫码
D6演示脚本、录屏、README、架构图、已知限制可交付

4. T0 验收

  • 一键启动，健康检查全绿
  • 虚拟扫描 5s、连接 10s
  • 配网/绑定落库，归属正确
  • 遥测 2s 推送，命令 1s ack
  • 场景逐项状态，run 日志
  • 断连/重启恢复，异常有反馈

5. T1 验收

  • 手机扫描到板子与 Service UUID
  • 连接并读 FFF1
  • 写 FFF2 配网，MQTT 上线
  • 订阅 FFF4/FFF5，写 FFF3 有 ack
  • 断连/重连/错误 token 有反馈
  • PC 侧 bleak 或手机至少一条链路可复现

6. 端到端场景

管理员建型号→ 用户登录→ 添加设备→ 绑定家庭→ 控制设备→ 执行场景→ 后台看日志/审计

7. 安全与性能

安全

  • 越权/未登录/过期 token
  • 命令归属校验、配网 token 重放
  • 限流、输入校验、错误脱敏
  • 依赖漏洞扫描

性能

  • 设备列表 200 条分页
  • WS 100 连接/遥测频率
  • 命令成功率/延迟
  • 小程序首屏/图片体积

8. 交付物

  • 源码 + README + 启动脚本 + 环境记录
  • OpenAPI/数据字典/架构图
  • T0/T1 测试报告与失败结论
  • 体验版二维码 / 演示录屏
  • 5–10 分钟演示脚本
  • 已知限制与后续路线

9. 验收标准

  • 新人按 README 可启动
  • 体验版扫码可用
  • T0 全绿；T1 至少 1.1–1.4
  • 端到端流程一次走通
  • 安全/性能无阻断问题
  • 演示脚本/录屏/文档齐全

10. 收尾

P5 完成后进入维护/迭代：真实硬件适配、更多设备型号、场景模板、运营功能。计划文档随实现更新，不保留过期描述。
