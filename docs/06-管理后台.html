06 · Admin Console

PC 管理后台

管理后台不是“再画一套页面”，而是让运营能配置设备型号、管理用户/家庭、查看设备与命令、 模拟信号、审计操作。表单与菜单必须能随权限和元数据变化。

Vue 3 + Element Plus RBAC JSON Schema 表单 审计 设备模拟器

1. 目标

  • 管理员能登录并只看到有权限的菜单/按钮。
  • 能维护设备型号、能力、命令元数据；新增型号后小程序无需改代码。
  • 能查用户/家庭/设备/绑定关系，处理解绑/迁移。
  • 能看遥测/命令/场景执行/审计日志，定位问题。
  • 能通过设备模拟器制造信号、断连、错误，支撑演示与测试。

3. 权限与菜单

角色

  • super_admin：全部权限，含管理员/角色。
  • ops：型号、库存、场景、模拟器。
  • support：用户/家庭/设备只读 + 基础处理。
  • viewer：只读仪表盘/日志。

实现方式

  • 后端 Guard 校验权限码；前端只负责隐藏。
  • 路由 meta 声明权限；菜单由权限树生成。
  • 按钮级 v-permission="'device_model:write'"。
  • 所有写操作落审计，含 before/after。

4. 动态表单（核心扩展点）

设备型号、能力、命令、场景动作都用 JSON Schema 驱动，避免每来一个型号就改后台页面。

{
  "type": "object",
  "properties": {
    "key": { "type": "string", "title": "能力标识" },
    "type": { "type": "string", "enum": ["boolean", "number", "enum"] },
    "min": { "type": "number", "title": "最小值" },
    "max": { "type": "number", "title": "最大值" },
    "unit": { "type": "string", "title": "单位" },
    "control": { "type": "string", "enum": ["switch", "dial", "slider", "segmented", "remote"] }
  }
}

新增字段只改 schema + 渲染器，不复制表单；复杂字段（能力列表、命令参数）用子表单/JSON 编辑器。

5. 设备型号编辑器

基础信息

型号 code、名称、品类、品牌、图片、状态；code 唯一，发布后不轻易改。

能力与命令

能力列表（key/type/range/control）、命令列表（name/params）、UI schema；保存前做 schema 校验。

发布与版本

草稿/发布/下架；已绑定设备保留旧版本元数据；新增版本不破坏历史数据。

预览

用 schema 渲染一个控制区预览，保存前就能看到小程序会怎么显示。

6. 设备库存与绑定

  • 批量导入 serial/model，生成未绑定设备。
  • 查看绑定用户/家庭/房间/时间；支持解绑、迁移、标记故障。
  • 解绑需二次确认 + 原因；写审计并通知用户。
  • 设备详情展示最近遥测、命令、场景执行、在线状态。

7. 设备模拟器

选型号→ 创建虚拟设备→ 发遥测→ 模拟断连/错误→ 观察小程序/日志

模拟器调用 /admin/simulator/*，通过设备引擎发 MQTT/虚拟 BLE，不是直接改前端状态。

8. 日志与可观测

页面关键字段用途
遥测日志deviceId、ts、metrics、来源排查数据异常/延迟
命令日志cmdId、设备、发起人、状态、耗时、错误排查控制失败
场景执行runId、场景、触发、逐动作状态排查联动失败
审计actor、action、resource、before/after、IP合规与追责

9. 后台体验与实现

  • 列表：筛选、分页、排序、列配置、导出；空/加载/错误三态。
  • 详情：抽屉/独立页；关联用户、家庭、设备、日志可跳转。
  • 危险操作：二次确认 + 输入原因；按钮加载态防重复。
  • 响应式：PC 优先，1366 宽可用；不做手机端管理。

10. 验收

  • 四个角色登录后菜单/按钮不同
  • 新增设备型号并发布，小程序无需改代码即可看到
  • 动态表单能编辑 capabilities/commands
  • 设备库存可查绑定关系并解绑/迁移
  • 模拟器能发遥测/断连，前端实时变化
  • 遥测/命令/场景/审计日志可筛选
  • 越权操作 403，写操作有审计
