P02–3 天

基础设施与工程化

monorepo、TypeScript、CI、数据库、Docker/本机服务、共享包、文档骨架。

验收：可安装、可启动、可测试、可复现

账号、家庭与权限

微信登录（mock/真实）、管理员 JWT、家庭/成员、RBAC、设备绑定基础表。

验收：登录、家庭、权限闭环

设备、模拟引擎与场景

设备模型/能力、配网、绑定、虚拟 BLE、MQTT/WS、遥测、命令回执、场景执行器。

验收：设备落库并绑定，信号可走通
P36–8 天

小程序用户端

登录、首页、全屋、动态设备控制、添加设备、场景、消息、能耗、我的。

验收：核心闭环可演示，3 秒找到运行设备
P45–7 天

PC 管理后台

仪表盘、用户/家庭、设备型号/能力、库存、场景模板、日志、审计、设备模拟器。

验收：管理员可运营，动态表单可扩展
P55–6 天

联调、测试与交付

T0 单机全链路、T1 ESP32 BLE、E2E、安全/性能、Docker/HTTPS、体验版、演示脚本。

验收：端到端通过，可复现交付

关键架构决策

元数据驱动，不写死按钮

设备型号、能力、命令 schema 存数据库；小程序按能力动态渲染，未知能力有通用降级。新增设备类型不需要复制页面。

架构与扩展机制 →

信号链路：MQTT + WebSocket

设备引擎发 telemetry，服务端订阅落库，WS 推送前端；命令走 REST → MQTT → 设备 → ack。不是前端定时器假动。

设备引擎 →

T0 单机全虚拟，T1 开发板 BLE

一台电脑跑通扫描/连接/配网/绑定/遥测/控制；ESP32 作为 BLE 外设做真实信号验证。两条路径都有验收矩阵。

设备测试与 BLE 联调 →

设备添加必须落库并绑定

配网成功后写入 device / device_binding，带 user_id / family_id / home_id / room_id；管理后台可查、可解绑、可迁移。

数据模型 →

空缺入口：A 类新设计，B 类“正在开发中”

设计稿有按钮无页面的入口：必要/设置类按现有 UI 风格新设计最小页面；商城/发现/健康生活等丰富版块点击提示“正在开发中”。无死按钮，计入 P3 验收。
