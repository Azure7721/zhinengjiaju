03 · Identity & Family

账号、权限与家庭体系

小程序用户、管理员、家庭成员、设备归属是四条不同的身份关系。 本文档定义登录、Token、角色、邀请、设备绑定与越权防护。

微信登录 + mock JWT / Refresh 家庭角色 管理员 RBAC

1. 四类身份

身份登录方式作用域存储
小程序用户微信 code2session；开发期 mock自己的家庭与设备user + wechat_account
家庭成员加入家庭后获得角色某个家庭/住宅family_member
管理员邮箱/密码 + JWT后台运营范围admin_user + role
设备配网 token + serial绑定到家庭/用户device + device_binding

2. 小程序登录

2.1 真实流程

  1. 小程序调用 uni.login({ provider: 'weixin' }) 获取临时 code。
  2. 小程序把 code 发给 POST /api/v1/auth/wechat/login。
  3. 服务端用 AppID/Secret 调微信 code2Session，得到 openid / unionid / session_key。
  4. 服务端按 openid 找/建 user 与 wechat_account，签发 access/refresh token。
  5. 小程序保存 token，后续请求带 Authorization；WebSocket 用 token 鉴权。
// 响应示例
{
  "ok": true,
  "data": {
    "accessToken": "eyJ...",
    "refreshToken": "eyJ...",
    "expiresIn": 7200,
    "user": { "id": "u_1", "nickname": "Vivian", "avatar": "..." },
    "families": [{ "id": "f_1", "name": "Vivian的家", "role": "owner" }]
  }
}

2.2 开发期 mock

没有 AppID 时，服务端提供 POST /auth/wechat/mock，用 { nickname, mockOpenId } 直接建号；通过环境变量 WECHAT_MOCK=true 启用。**生产环境必须关闭**。

安全：session_key 不明文存库；只存 hash 或加密值。mock 登录只允许在 NODE_ENV!=production 下启用。

2.3 登录方式选型分析（已定）

方式用户操作资质要求难度成本结论
① 微信静默登录（wx.login → code2Session 换 openid） 零输入，打开即登录 个人主体即可，仅需 AppID ★ 低（后端一个接口 + openid 唯一键建号） 0 采用 主登录方式
② 微信手机号快速填充（getPhoneNumber） 点一下授权 企业主体 + 微信认证（约 300 元/年），个人主体不可用 ★★ 中（解密接口 + 隐私弹窗声明） 认证费 不做 资质不满足
③ 手机号 + 短信验证码 输号 → 看短信 → 输码 短信签名/模板备案 ★★ 中（短信通道、Redis 验证码、防刷限流） 按条约 3–5 分/条 不做 演示无价值
④ 注册制账号密码 注册表单 + 找回流程 无，但微信规范不允许强制注册才能用核心功能 ★★★ 高（哈希存储、找回、防撞库） 0 仅后台 管理员/测试账号
  • 难度排序：① < ④ < ③ < ②（② 卡在企业认证，个人主体直接不可用）。
  • 本项目采用：① 微信静默登录（主） + 2.2 mock 登录（开发/无 AppID） + 管理员账号密码（见 §3）。手机号/短信均不做。
  • 扩展点：后端 AuthProvider 策略注册表（wechat / mock / password），将来加手机号登录只加一个策略，不动业务代码。
  • 数据：users 以 openid 唯一索引自动建号；unionid / phone 可空；登录方式记入 auth_provider，天然支持“先微信登录、后绑定手机号”。
  • 登录页（无设计稿）：按 00 的 A 类规则新设计——产品图 + 主色登录卡 +「微信一键登录」主按钮 +「演示账号」次按钮 + 底部隐私协议入口；页面路径 pages/login/index（见 05 页面表）。
演示形态：纯个人演示、不挂公网服务器、不发布上线时，① 仍然可用——后端跑本机，真机体验版「打开调试」跳过域名校验直连局域网 IP。完整说明见 09 · 零备案运行形态。

3. Token 与管理员登录

Token 设计

  • Access Token：JWT，2 小时；含 user/admin id、角色、familyId 列表。
  • Refresh Token：随机串，7–30 天；存库可撤销；轮换。
  • WebSocket 首帧/query 带 token；服务端校验后绑定连接。
  • 登出/改密/移除成员时撤销 refresh token。

管理员登录

  • 邮箱/密码；Argon2id 或 bcrypt 哈希。
  • 登录失败限流；连续失败锁定。
  • 角色：super_admin / ops / support / viewer。
  • 所有写操作写 audit_log。

邀请流程

owner 生成邀请码→ 分享/扫码→ 用户登录→ 校验邀请码/有效期→ 写入 family_member→ WS 通知

5. 设备绑定与归属

设备添加不是“在内存里加一条”，而是完整链路：

创建配网会话→ 扫描/连接→ 写 token→ 设备上报 serial→ 校验会话→ 写 device→ 写 device_binding
字段说明
device_id设备实例主键
user_id绑定操作者/归属人
family_id / home_id / room_id归属家庭/住宅/房间
bound_at / unbound_at当前绑定 = unbound_at IS NULL
sourceble / qr / manual / admin

设备迁移/解绑必须校验 owner/admin 权限，并写审计；设备被解绑后立即停止向该家庭推送。

7. 安全清单

  • 密码哈希（Argon2id/bcrypt），不存明文
  • JWT 短有效期 + refresh 轮换 + 撤销
  • 登录/命令/配网限流
  • 越权校验在后端，不信任前端 familyId
  • 配网 token 一次性、过期、哈希存储
  • 审计所有写操作与设备绑定变更
  • 敏感配置走环境变量，不入库/不入仓

8. 验收

  • 微信 mock 登录成功，返回 family 列表
  • 有 AppID 时：真机体验版（打开调试）微信一键登录成功，users 落 openid
  • 登录页无设计稿，按 A 类新设计：微信一键登录 + 演示账号 + 隐私协议入口
  • 管理员登录成功，菜单按角色显示
  • member 不能添加/移除设备，返回 403
  • 非家庭成员不能读取设备/场景
  • 绑定设备后 DB 归属正确，后台可查
  • 解绑/迁移后原家庭不再收到推送
  • 所有写操作有 audit_log
