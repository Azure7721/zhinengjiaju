Phase 2 · Device & Automation

P2 · 设备、模拟引擎与场景

目标：设备可建模、可发现、可配网、可绑定、可控制；信号从引擎/MQTT 来，不靠前端假动； 场景能执行并逐项记录。这是整个项目最核心、最难的一段。

7–9 天 设备模型 虚拟 BLE MQTT / WS 场景执行器

1. 阶段目标

  • 设备型号/能力/命令元数据 CRUD
  • 设备库存、配网会话、绑定/解绑/迁移
  • 设备引擎生成 telemetry，支持命令/ack/故障注入
  • 虚拟 BLE 完成扫描/连接/配网
  • MQTT + WebSocket 实时链路
  • 场景 DSL、执行器、逐动作状态、run 日志
  • T0 单机全链路通过

2. 前置条件

P1 验收通过：登录、家庭、权限、绑定表可用。

3. WBS

时间任务产出
D1–D2设备型号/能力/命令 schema；设备库存；元数据校验后台可建模
D3配网会话状态机；绑定/解绑/迁移 API；审计绑定落库
D4虚拟 BLE WebSocket 服务；Adapter 接口；4+1 虚拟设备扫描/连接/读写
D5设备引擎：telemetry 生成、命令消费、ack、故障注入信号闭环
D6MQTT 主题/桥接；WS Gateway；状态/遥测推送实时链路
D7–D8场景 DSL、执行器、调度、run/action 日志场景可执行
D9T0 测试脚本、种子、联调、文档T0 可复现

4. 设备域

元数据

device_model.metadata_json 存 capabilities/commands/UI schema；新增型号无需改前端页面。

设备实例

serial 唯一；home/room；状态在 device_state；绑定在 device_binding。

配网

session token 一次性/过期；scan → connect → provision → bind；失败原因可读。

命令

cmdId 幂等；超时重试；ack 落库；WS 推送；越权拒绝。

5. 信号链路

device-engine
telemetry / command / ack / presence / 故障注入
↕MQTT（Aedes）
server
订阅、落库、命令下发、WS 推送
↕WebSocket
miniapp / admin
实时状态、命令结果、场景进度

虚拟 BLE 与真实 BLE 共用 Adapter 接口；小程序端通过环境变量切换。

6. 场景执行器

  • 触发器：manual / schedule / condition / deviceEvent。
  • 动作：设备命令 + 延迟 + 失败策略；逐动作状态。
  • run 状态：queued/running/success/partial/failed/cancelled。
  • 防循环、冷却、并发控制、幂等。

7. 验收标准

  • 后台新增型号，小程序无需改代码可见
  • 虚拟 BLE 扫描/连接/配网/绑定成功
  • device/device_binding 落库，归属正确
  • telemetry 2s 内 WS 推送并落库
  • 命令 1s 内 ack，重复 cmdId 不重复执行
  • 场景逐动作状态可见，run 日志完整
  • 断连/超时/错误 token 有反馈
  • T0 测试脚本全绿

8. 风险

  • 设备抽象过度 → 先 4 类 + 1 未知能力，按真实需求扩展。
  • 配网状态复杂 → 先状态机与失败分支，再优化 UI。
  • MQTT 重复/丢失 → 幂等 + QoS1 + retained 只用于 state/presence。
  • 场景循环触发 → 事件链去重/深度限制。
  • 硬件未到 → 先 T0，T1 后置。

9. 下一阶段入口

P2 验收通过后，P3 小程序前台与 P4 管理后台可以并行；以 P3 为主。
