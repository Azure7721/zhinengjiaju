04 · Device Engine

设备引擎与信号适配

设备不是一个页面，而是“型号 + 能力 + 状态 + 命令 + 传输”的组合。 本文档定义可扩展的设备模型、适配器接口、模拟引擎、虚拟 BLE、MQTT 主题与配网状态机。

能力模型 Adapter 模式 MQTT 虚拟 BLE T0 + T1

1. 设计目标

  • 新增设备类型/能力不复制页面、不改核心业务。
  • 设备信号来自引擎/硬件，不是前端定时器。
  • 命令有幂等、超时、重试、回执、审计。
  • 同一套业务代码支持 Mock、虚拟 BLE、MQTT、真实 BLE。
  • 配网、绑定、解绑、离线、重连都有明确状态。

2. 设备模型与能力

2.1 三层对象

DeviceModel

型号/品类/能力/命令元数据，管理员维护，所有实例共享。

Device

具体实例：serial、home/room、在线状态、绑定关系。

DeviceState

最新状态（设备影子）：power、temperature、position、pm25、progress…

5. 虚拟 BLE（T0 基座）

用 WebSocket 模拟 GATT 语义，使小程序端可以在“真实 BLE”和“虚拟 BLE”之间切换，业务代码不变。

消息方向字段
scan.startclient → server{ serviceUUID }
scan.resultserver → client{ devices:[{deviceId,name,rssi,serviceUUID}] }
connectclient → server{ deviceId }
connectedserver → client{ deviceId }
discoverclient → server{}
servicesserver → client{ services:[{uuid,characteristics}] }
read / value双向{ serviceId, characteristicId, value? }
writeclient → server{ serviceId, characteristicId, value }
notifyserver → client{ characteristicId, value }
disconnect双向{ deviceId, reason }

虚拟设备包含：空调、窗帘、电视、净化器 + 1 个未知能力设备（验证降级）。

6. MQTT 主题与载荷

主题方向QoS载荷
device/{id}/telemetry设备 → 服务端0/1{ v, deviceId, ts, metrics }
device/{id}/state设备 → 服务端1 retained最新完整状态
device/{id}/command服务端 → 设备1{ v, cmdId, capability, name, params, ts }
device/{id}/ack设备 → 服务端1{ v, cmdId, status, error?, ts }
device/{id}/presence设备 ↔ 服务端1 retained + 遗嘱{ online, ts }
不要 retained 命令：命令只走 QoS 1、非 retained；state/presence 才 retained，避免新订阅者重放旧命令。

7. 模拟引擎

信号生成

  • 温度：25–27℃ 正弦/随机游走
  • 湿度：45–65%
  • PM2.5：20–80，可注入峰值
  • 进度：清洁/洗衣每 2s +1%
  • 在线：随机断连/恢复（可配置）

故障注入

  • 延迟、丢包、重复消息
  • 错误 JSON、超大 payload
  • 命令超时、ack 失败
  • 设备离线/重启
  • MQTT broker 断开

8. 命令总线

  1. 校验：登录、家庭归属、设备归属、能力/参数合法。
  2. 幂等：cmdId 唯一；重复请求返回原结果。
  3. 落库：status=pending；记录发起人/来源。
  4. 下发：MQTT 或 BLE；记录 transport。
  5. 等待 ack：超时（默认 5s）重试 1–2 次；仍失败标记 timeout。
  6. 更新：state/command 状态；WS 推送；写审计。

9. 配网状态机

idle → session_created → scanning → connecting → connected
     → provisioning → provisioned → binding → bound
     ↘ failed / expired / cancelled
  • 会话 token 一次性、5 分钟过期、hash 存储。
  • 绑定必须带 session + serial + 当前用户/家庭。
  • 失败给明确原因：超时、token 错误、设备已被绑定、WiFi 失败。
  • 重复绑定要提示“设备已属于其他家庭”，并提供管理员解绑流程。

10. 新增设备类型/能力的步骤

  1. 管理后台新增 device_model，填写 capabilities/commands。
  2. 选择已有控件；如需新控件，在小程序注册 control → component。
  3. 设备引擎/真实设备实现对应命令与遥测。
  4. 用“未知能力设备”验证降级，用新设备验证控制。
  5. 补契约测试与 E2E；不需要改首页/设备详情结构。

11. 验收

  • 新增一个设备型号，小程序无需改代码即可显示/控制
  • 未知 capability 渲染通用控件，不白屏
  • 虚拟 BLE 完成扫描/连接/配网/绑定
  • MQTT telemetry 落库并 WS 推送
  • 命令重复 cmdId 不重复执行
  • 超时/离线/错误 token 有明确 UI 反馈
  • 解绑后停止推送，后台可查审计
