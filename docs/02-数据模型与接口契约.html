02 · Data & Contracts

数据模型与接口契约

统一 REST、WebSocket、MQTT 与数据库的“同一套事实”。设备绑定、遥测、命令、场景执行 都必须可追溯到人、家庭、设备和时间。

PostgreSQL + Prisma REST /api/v1 WS 事件 MQTT topics

1. 设计目标

  • 设备添加必须落库并绑定账号/家庭/住宅/房间，不能只存在前端。
  • 设备型号与能力用 JSONB 存，新增品类不改表结构。
  • 遥测是追加型时序数据，命令是状态机数据，场景执行有 run/action 级记录。
  • 所有写操作可审计；所有接口有统一错误码与幂等约定。
  • WS/MQTT 消息带版本字段，契约集中在 packages/contracts。

4. 索引与保留

关键索引

  • telemetry(device_id, ts desc)
  • command(device_id, created_at desc)、command(cmd_id) 唯一
  • device_binding(device_id) where unbound_at is null
  • scene_run(scene_id, started_at desc)
  • audit_log(actor_id, created_at desc)

保留策略

  • 遥测：演示保留 30 天，生产按天分区/时序库。
  • 命令/场景执行：保留 180 天；审计至少 1 年。
  • 图片/固件放对象存储，DB 只存 URL。
  • 软删除：设备/家庭用 status，不物理删除。

6. WebSocket 事件

连接：wss://host/ws?token=<access_token>；服务端校验 JWT 与家庭成员关系。

事件方向载荷
device.stateserver → client{ deviceId, online, state, updatedAt }
device.telemetryserver → client{ deviceId, ts, metrics }
command.updatedserver → client{ commandId, status, error? }
scene.run.updatedserver → client{ runId, status, actions[] }
notification.createdserver → client{ id, type, title, body }
presenceclient → server{ homeId, page }（在线态/订阅）

7. MQTT 主题

主题方向QoS载荷
device/{deviceId}/telemetry设备 → 服务端0/1{ v, deviceId, ts, metrics }
device/{deviceId}/state设备 → 服务端1retained 最新状态
device/{deviceId}/command服务端 → 设备1{ v, cmdId, capability, name, params, ts }
device/{deviceId}/ack设备 → 服务端1{ v, cmdId, status, error? , ts }
device/{deviceId}/presence设备 ↔ 服务端1{ online, ts } + 遗嘱消息

QoS 1 用于命令/回执；遥测可 QoS 0；retained 只用于 state/presence，不用于命令，避免重放。

9. 验收

  • 添加设备后，device + device_binding 可查，归属正确
  • 命令重复提交同一 cmdId 不重复执行
  • 遥测落库并按时间索引，WS 能实时收到
  • 场景执行有 run 与逐 action 记录
  • 管理员越权访问返回 403 并留审计
  • OpenAPI 与 contracts 一致，示例可跑
