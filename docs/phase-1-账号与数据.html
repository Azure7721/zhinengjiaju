Phase 1 · Identity

P1 · 账号、家庭与数据

目标：小程序用户能登录、创建/加入家庭；管理员能登录后台；权限与数据归属在服务端闭环。 这是后续设备绑定与场景执行的前提。

4–6 天 微信 mock/真实登录 JWT + Refresh 家庭角色 RBAC

1. 阶段目标

  • 微信 code2session + mock 登录可用
  • 管理员账号/密码登录，JWT/refresh，RBAC
  • 家庭创建、邀请、成员/角色、住宅/房间
  • 设备绑定表与基础 API 就绪
  • 越权访问被拒绝并审计
  • OpenAPI 与集成测试覆盖核心接口

P0 验收通过：数据库、迁移、server 空壳、CI 可用。

4. 登录实现要点

小程序

  • uni.login 获取 code。
  • 服务端 code2session；mock 模式跳过微信。
  • 按 openid 建/找 user；签发 access/refresh。
  • 返回 family 列表与当前角色。

管理员

  • Argon2id/bcrypt 哈希；失败限流/锁定。
  • JWT 含 adminId、角色、权限版本。
  • refresh 轮换/撤销；改密使旧 token 失效。
  • 登录/失败写审计。
Mock 登录：只在 WECHAT_MOCK=true 且非生产启用；上线前必须关闭并清理测试账号。

7. 验收标准

  • mock 登录成功，返回 token 与 family
  • 管理员登录，四角色菜单不同
  • owner 创建家庭/邀请；member 加入
  • member 添加设备返回 403
  • 非成员读取家庭/设备返回 403/404
  • refresh 轮换，旧 refresh 失效
  • 写操作有 audit_log

8. 风险

  • 没有 AppID → 先用 mock，真实流程用测试号验证。
  • 家庭角色边界不清 → 以权限矩阵为准，前端只做展示。
  • Token 过期体验 → 自动 refresh + 失败跳登录。
  • 测试数据污染 → seed 与重置脚本。
