Phase 3 · Mini Program

P3 · 小程序前台

目标：把用户端核心闭环做出来——登录、看状态、控设备、加设备、执行场景、看能耗。 页面贴合设计稿，控制区由能力动态生成，状态来自服务端。

6–8 天 uni-app + Vue 3 750rpx 动态控件 WS 实时

1. 阶段目标

  • 登录/家庭选择、TabBar、设计令牌
  • 首页/全屋/设备详情/场景/添加设备/能耗/我的
  • 四类设备动态控制 + 未知能力降级
  • 添加设备 → 配网 → 绑定 → 首页出现
  • WS 实时、离线缓存、命令三态
  • 3 秒找到运行设备、操作 ≤2 步、有反馈

2. 前置条件

P2 验收通过：设备/配网/信号/场景 API 可用；T0 虚拟 BLE 可扫。

3. WBS

时间任务产出
D1uni-app 脚手架、pages.json、TabBar、设计令牌、通用组件空壳可跑
D2登录/家庭选择、user store、token 拦截、mock 登录登录闭环
D3首页：环境/房间/运行设备/快捷开关/空态首页可用
D4全屋：平面图热点/分区/快捷模式全屋可用
D5设备详情：状态区 + 动态控件 + 命令三态4 类设备可控制
D6添加设备/配网：扫描、连接、绑定、失败引导设备可添加
D7场景列表/详情/执行；消息；能耗；我的信息架构完整
D7+入口盘点：A 类空缺页（设置/家庭管理/设备编辑等）按现有 UI 风格新设计；B 类丰富版块接 UnderDev 占位无死按钮：A 类可走通、B 类有“正在开发中”反馈
D8WS 实时、离线缓存、异常态、真机适配、联调核心闭环

4. 页面优先级

优先级页面原因
P0登录、首页、设备详情、添加设备核心链路，必须最先可用
P1场景、全屋、能耗演示亮点，紧随其后
P2消息、我的；A 类空缺页（设置/家庭管理等）；发现/商城占位补全信息架构；A 类新设计、B 类“正在开发中”占位

5. 组件与状态

组件

  • NavBar、TabBar、PageShell
  • Stat、DeviceCard、SceneCard、Empty、Sheet
  • PowerSwitch、TemperatureDial、CurtainSlider、TvRemote、PurifierPanel
  • Feedback：Toast、InlineStatus、RetryBar、UnderDev 占位

Store

  • device：列表/状态/在线/命令
  • scene：列表/执行/进度
  • energy：范围/聚合
  • user：登录/家庭/角色
  • ui：Toast/弹层/加载

6. 实时与异常

  • WS 断线重连，重连后拉全量状态。
  • 命令乐观更新，失败回滚 + 重试。
  • 离线：只读缓存 + 明确标识；恢复后同步。
  • 所有列表四态：有数据/空/加载/失败。
  • 配网失败：token/超时/已绑定/WiFi 失败分别提示。

7. 验收标准

  • mock 登录 → 家庭 → 首页
  • 3 秒内指出运行设备
  • 首页到调温 ≤2 步
  • 4 类设备可控，未知能力不白屏
  • 添加设备 → 绑定 → 首页出现
  • 场景执行逐项状态可见
  • 刷新/重连状态不丢
  • 主流 iPhone/Android 不破版
  • 无控制台报错
  • A 类空缺页（设置/家庭管理/设备编辑等）按现有 UI 风格可走通
  • B 类版块（发现/商城/健康生活/会员等）点击均提示“正在开发中”，无死按钮

8. 风险

  • UI 还原耗时 → 先令牌/组件，最后两天统一打磨。
  • 动态控件抽象过度 → 先 4 类 + 未知降级，按需扩展。
  • 开发者工具 BLE 限制 → 用虚拟 BLE 做日常，真机做 T1。
  • 状态不一致 → 单一 store + 服务端为准。

9. 下一阶段入口

P3 与 P4 管理后台 可并行；P5 做联调与交付。
